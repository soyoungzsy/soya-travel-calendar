# 目的地介绍覆盖检查

本报告覆盖公开资料库的79张季节卡、75个去重目的地；不包含私人地点，不把地图上的行政地名算成已建攻略。全量检查是本地结构审计，不代表本轮逐一重读了75个目的地的外部来源。

## 开普敦案例的两个原因

1. 旧版 usability.css 隐藏了所有 .poi-inline 内的标题和简介。对没有额外历史段的短卡，剩下的几乎只有季节行，形成用户截图中的大片空白。这条全局规则已修复，作用于所有内嵌景点详情。
2. 开普敦原有介绍只是季节与天气，两个景点也只有一句短述。本轮按开普敦市政府、旅游局、SANParks、罗本岛及第六区博物馆实际读取的正文，补入城市定义、港口与人口迁徙、种族隔离与社区记忆、生态，以及5项具体体验。

## 如何理解下面的状态

- “概览缺失”是空字符串；“概览待扩写”是短于45字或与季节提示完全相同的审校标记。文字长不等于内容好，文字短也不自动等于事实错误。
- “背景待补审”表示未在独立目的地故事或景点历史字段中记录背景。自然目的地也需要地理、生态或科学背景，不强套历史人物。
- “已记录景点背景”不等于城市介绍完整；“已有概览”不等于已经达到开普敦的新样板标准。
- 本轮已有文字的标题与简介恢复显示，不代表所有短卡已完成深入扩写。下表如实保留剩余缺口。

修复前：79张卡的概览字段均非空，但54张少于45字、64张复用季节提示。修复后按去重目的地统计，仍有61处需概览扩写复审、62处需背景字段补审。两类可重叠，不能相加。

## 后续补全标准

每个目的地至少回答：这是什么地方、地理范围是什么；为何值得亲自去；有哪些有来源的历史、人物、作品或自然故事；到现场怎样理解它；哪些信息随日期变化。先补内容基础最薄弱的城市，再扩展深层书影音。无法核实的故事不编写，来源说明继续留在小提示中。

运行 `npm run content:audit` 可复查字段缺口。脚本不访问外网，不会把旧资料升级为本轮核验。
