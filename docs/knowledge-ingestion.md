# 旅行百科：一套资料、两个入口

更新：2026-10-20

日期年历和 `/encyclopedia` 共用 `data.mjs`、`guide-catalog.mjs`、`knowledge.mjs`、美食和阅读目录。百科只改变浏览与筛选方式，不维护第二份目的地事实。相同ID的收藏在两处通用。地图的地理单元另作几何用途，不等于逻辑国家目录。

## 为什么此前内容显得薄

原型最初以目的地概览和两三条 highlights 启动，部分城市未逐景点补全资料；“有一个官网链接”不代表已完整读取该城官方攻略。国家级旅游局也不足以覆盖城市、区县的短期花况、小景点、地方饮食与预约。这是实际覆盖缺口，不能用“权威来源”四个字掩盖。

当前每条景点应分别补足：具体看什么、为什么重要、怎样观看/体验、必要的历史与人物、适合季节、游览时间的性质（官方路线或编辑估计）、开放/预约等时效项、逐事实对应来源、摄影主题与许可。没有实质增量的条目直接呈现已有内容，不再用展开交互制造“还有很多”的错觉。

## 获取顺序与来源角色

| 层级 | 用途 | 本轮实际示例 |
| --- | --- | --- |
| 国家旅游局与国家文化遗产机构 | 国家概览、主要文化事实、国际访客信息 | 埃及旅游和文物部的卢克索/卡纳克官方介绍 |
| 省、州、自治区文旅 | 跨城市路线、区域季节与重要目的地 | 伊尔库茨克州官方旅游门户、新疆文旅厅草原线路 |
| 城市、区县文旅与政府 | 地方景点、村落历史、花况与当年活动 | 漠河文旅局北极村简介、博州冬季旅游与规划 |
| 景区、博物馆、保护区、科学机构 | 开放预约、展陈、步道与科学条件 | 贝加尔湖博物馆、NOAA极光观测指引、科学院漠河极光观测 |

宣传页适合发现线索；科学概率、极光观测、冰面安全、票务开放不能只凭旅游宣传。规划建设不等于已经开放。长昼、白夜不写成真正的极昼；漠河偶发极光不包装成稳定旅游季。

## 从资料到产品的流程

1. 建立机构目录，记录国家/省州/城市/区县、官方关联证据、官网与栏目地址。先核验机构归属，再采内容。
2. 查看站点地图、正式旅行指南HTML/PDF、官方地图与活动栏目。有RSS/API再按相应许可接；接口存在与免费再分发不是一回事。
3. 保存来源标题、发布时间/查阅日、正文访问层级和原始URL。检索摘要、超时页面、历史PDF分别标记在内部来源资料；不把“没抓到”写成“没有”。
4. 按景点实体与季节拆分知识，不按文章整页堆积。每条事实保留来源指针；同一景点不同季节使用同baseId与不同变体。
5. AI提取候选事实与游览建议，人工/程序复核名称、坐标、季节、时间、来源与图片主题。原创中文解释与短原文摘句、翻译分别保存。
6. 景点、地方饮食、行前阅读、摄影分别核许可。公开网页可读不等于全文或照片可转载；优先CC/公有领域或旅游媒体库明确许可，保留署名与修改说明。禁止用别处同类风景、别的菜或AI图片假冒实拍。
7. 以可审阅的增量更新单一内容目录；发布前检查去重、链接、季节、价格语义和页面排版。数量由实际分发资料实时计算，不把地图入口数冒充知识覆盖。

## 自动化与引用的边界

- 适合先自动化的是“发现更新→生成候选差异→编辑复核”，不是未经复核直接写公开攻略。
- 稳定历史事实与季节规律可低频复核；节庆、花况、潮汐、预约、票价等保留有效期和对应运营方，未取得最新数据时不作当天保证。
- 官方原话可作为有来源的短摘句帮助读者判断，长篇应写原创解释或引导阅读原文。无法确认许可的全文、旅游地图与书籍，不镜像整库。
- UNESCO可提供RSS/XML/GeoRSS/XLS/KML等名录格式，但syndication另有再分发条件；单页具体文字许可与整库许可应分开判断。
- 检索可以建立在同一套条目的标题、地区、主题与来源上。当前先完成分层浏览；不把语义搜索当成知识覆盖不足的替代品。

## 本轮可检验增量

新增贝加尔湖、赛里木湖、漠河各夏冬两张季节卡，7个官方核验景点；扩大罗弗敦秋冬观测窗口；6张同地不同季真实摄影。美食31项逐项审查，29项取得实拍，2项保留明确缺口与许可恢复点。没有把尚未采集的全球城市、区县内容算作收录。
