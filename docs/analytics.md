# 产品埋点与访问报表

报表路径：`/insights`。仅当前 Sites 所有者账号登录后可查看；匿名或其他账号不能读取数据接口。使用现有 Sites 的 D1 持久存储，不新增阿里云服务器或购买第三方统计套餐。

## 数据口径

| 指标 | 计算方式 |
| --- | --- |
| 访客数 UV | 允许统计且成功上报的浏览器标识去重，非真实人数 |
| 访问次数 | 单标签页会话去重；30分钟无有效活动后切分，刷新延续 |
| 页面浏览 PV | 每次初始化且允许统计时进入网页的次数 |
| 点击量 | 明确标记的语义操作，不读取按钮全文、输入值或DOM快照 |
| 有效停留 | 页面在前台且60秒内有操作才累计；每15秒心跳，单次最多15秒 |
| 平均停留 | 所选范围内累计有效停留÷访问次数 |
| 复访比例 | 本周期内曾于之前自然日来过的浏览器÷周期访客，观察历史最多90天 |
| 最长动线 | 一次访问中 page/view/click 步数最多的真实有序路径；排除心跳和性能事件 |
| 常见动线 | 完整路径相邻重复步骤合并后分组，按出现次数排序 |
| 关键功能使用 | 独立点击次数，不伪装为严格有序转化漏斗 |

统一使用 Asia/Shanghai 的自然日。每天访客不可直接相加当作周/月去重访客。用户可能拒绝统计、换设备、清空存储、拦截请求；网页打不开的人无法被前端埋点观察。报表不回填上线前历史。

## 采集与访问控制

- 首次访问明确允许后才生成随机统计标识并发送数据，可在页尾关闭。
- 公开数据目录限定实体ID；个人地点与证件面板不采集内容。预算、日期只记录“调整了该筛选项”，不记录金额、具体旅行日期和出发城市。
- 不发送姓名、号码、原图、OCR、私人备注、输入值、完整URL、精确地理位置、IP或完整User-Agent字段。
- 标识服务端加盐SHA256后入库。盐与所有者邮箱只通过 Sites 运行时secret配置，不写源码或前端。
- 接口仅接受同源JSON、严格字段白名单、每批最多25条及24KB；事件ID去重；单浏览器每分钟有限流。限制能减少误上报，无法证明访问者一定是真人。
- `analytics_events` 是行为明细，`analytics_visitors` 保存首次/最近观察日，`analytics_daily` 是按日与流量类型聚合。
- 原始记录与日报保留90个自然日，采集请求执行清理；无新采集时不承诺定时物理删除。
- 所有者登录后访问排除出真实流量。`?analytics_test=1` 为验收测试流量，报表可单独切换，升级提醒只能读取 live。
- 路径最多取2000个最长会话/50000条操作，达到上限必须展示提示；UV、点击等汇总始终独立全量SQL计算。

## 监控与付费边界

先以连续3个完整自然日各有100位已采集访客作为“值得评估托管升级”的提醒阈值；这不是容量上限。数据达到阈值或发生采集失败时提醒所有者，平常不重复通知。访问量本身不证明国内网络可达；必要时结合用户打不开反馈与实际加载测试判断。

监控可以通过当前 Sites 的 `read_database_overview` / `read_database_table_rows` 读取 `analytics_daily`，筛选 `traffic=live` 与完整自然日。工具失败或没有行时分别记为不可读取/尚无已采集数据，不写成没有用户。

任何服务器购买、充值、自动续费或付费接口都需再次由用户确认；监控绝不执行付款。当前国内迁移与ECS购买不继续推进。

## 部署

`.openai/hosting.json` 声明 `d1: "DB"`；`db/schema.mjs` 用 `npm run db:generate` 生成追加式 `drizzle/` 迁移。构建复制全部SQL与Drizzle元数据到 `dist/.openai/drizzle/`，Sites 在部署时应用。请求处理不建表。

配置 secret：`ANALYTICS_OWNER_EMAIL` 为 Sites 当前所有者的已验证邮箱，`ANALYTICS_HASH_SALT` 为稳定随机盐。Sites 身份头由平台验证；独立Node/ECS环境不信任浏览器自行传来的同名头，未配数据库与身份代理时采集及报表保持不可用。当前Node离线/迁移包不提供集中统计数据库。

先构建，再运行测试；用临时SQLite执行真实迁移与查询，验证去重、隐私拒收、权限、跨日复访与聚合。线上验收写入test流量并由受保护报表/数据库读回，不污染live。
