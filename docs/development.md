# Development and deployment / 给开发者

Ordinary users can skip this file. Node 22.12+ is required. Use npm ci, npm test and npm run build. npm run dev binds to127.0.0.1. The public repository contains no author's Sites project ID; configure your own hosting identity if using Sites. For plain static hosting, publish dist/client at the site root. The app works with dated fallback data when reference APIs are absent; the optional Worker in worker/index.js serves static assets and /api/fx, /api/interest and the disconnected travel-search status endpoint. Do not put server keys in frontend variables.

The build produces dist/client and dist/server plus a generic hosting manifest. No account creation, storage binding, domain registration or deployment is automatic. Self-hosting costs and access from different networks depend on your provider. A custom domain alone does not guarantee availability in mainland China.

Original curated data lives in src/data.mjs and src/discoveries.json; rich guides in src/travel-guides.json; image credit metadata in src/media.json. Personal records use a separate versioned local key and never change the curated dataset. Their months are user notes, not verified recommendation windows. Map-only private entries have no auto-priced itinerary.

Optional document recognition uses pinned Tesseract.js 7 and English/MRZ language data. `predev` and `prebuild` copy dependency assets into ignored `public/ocr/`; commit the preparation script and lockfile, never the generated directory or a user's scan. Deploy `dist/client/ocr/` at the site root with correct JS/WASM/gzip bytes; no CDN or remote OCR fallback is configured. Assets load only when the person asks to recognize a photo; do not preload them with the globe. A selected photo remains in page/worker memory only; no OCR endpoint is implemented in the Worker. Parser output is allowlisted, previewed, editable and explicitly confirmed; only a final profile save persists it. Profile restoration also strips unexpected fields. The original photo and raw OCR text never belong in localStorage or destination export. English labels and Korean grant notices are best-effort; TD3 passport expiry uses MRZ check digits. Other scripts/layouts, PDF/HEIC, authenticity, unused entries and entry eligibility are not supported. The portable single-HTML download disables photo OCR and preserves manual entry.

Tests must use fictional fields and synthetic MRZ data. Never capture real documents in screenshots or commit private OCR diagnostics. To review locally: open the top-right profile icon, choose a synthetic image, recognize, inspect editable fields, cancel/retry and confirm; then save and reopen. Inspect network traffic to verify OCR resources are same-origin and no photo POST occurs. Test no-update-before-confirm, cancel, storage denial, invalid dates, damaged MRZ and cleanup on close. Manual or AI-assisted review is not independent real-user research.

MRZ recognition checks the two date check digits and, where possible, the full TD3 composite. OCR often damages filler runs: a date-only candidate with passing date digits but a failing full line carries an explicit warning and still requires confirmation. Failed date checks produce no expiry. This is a transcription aid, never authentication of a passport.

Upgrade: export personal places first; install a fixed new release; retain the same browser origin if you want existing site storage, or import your backup on a different origin. File-mode storage differs between browsers, so keep a JSON backup. Roll back shared source with a revert commit or a previous release; do not rewrite published tags. Code rollback does not restore deleted browser data. Restore lists by importing your backup; duplicate records are skipped and existing notes retained.

Public travel-content enrichment lives in `src/food-catalog.json` and `src/reading-catalog.json`. Maintain exact destination mappings, source titles/authorities, check dates, body/excerpt/catalogue states and editorial-versus-factual wording. `npm run knowledge:check` calculates the same counts and reference ledger as the footer; it does not access the internet or reverify bodies. New public records require evidence review and a PR. The withheld UNESCO bulk index must stay out of public paths until reuse terms are explicitly resolved; existing provenance metadata is not a permission grant. See `docs/knowledge-base.md`.
